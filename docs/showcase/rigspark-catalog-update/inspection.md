# RigSpark catalog update demo inspection

1. **One-liner:** RigSpark updates signed local-LLM advice catalogs without replacing the application.
2. **Audience:** Local-LLM users who want current recommendations while keeping normal advice offline.
3. **Distinct behavior:** A catalog revision is published and activated independently of the RigSpark binary.
4. **Headline flow:** `catalog --status` shows bundled provenance -> `catalog --update` verifies revision 1 -> Models shows the same active revision.
5. **Real surfaces:** `README.md`, `crates/rigspark-cli/src/native.rs`, `crates/rigspark-gui/static/index.html`, and fresh browser-fixture captures.
6. **Strongest claim:** "Updates verify an Ed25519 signature and model schema before atomic activation."
7. **Surprising truth:** A failed later download leaves the verified revision active.
8. **Visual language:** near-black `#08090c`, warm white, mint status accents, coral mascot; Avenir Next and monospace terminal text.
9. **Strongest visual:** CLI revision 1 output beside the Models view reporting revision 1.
10. **Try it:** `rigspark catalog --update`.
11. **Lexicon:** RigSpark, catalog, revision, digest, Models view, signed snapshot, offline recommendations, Update catalog.
12. **Tone:** terminal; the feature is a trust/provenance workflow spanning a command and an operational UI.

CLI values were captured on 2026-10-02 from an isolated `RIGSPARK_HOME` against the official signed catalog channel. GUI captures were generated by RigSpark's disposable native browser fixture; they show the tested revision activation and offline-retry states without changing user data.
